# Project Layout

MakeCode Arcade projects have a fixed structure. Files outside this structure are ignored by the compiler, even if they're in the repo.

## Canonical layout

```
project-root/
├── .github/workflows/        ← Optional CI (see references/testing.md)
├── .vscode/                  ← Optional VS Code helpers
├── assets/                   ← Optional source PNGs (NOT loaded by MakeCode; for human reference)
├── .gitignore
├── pxt.json                  ← REQUIRED. Project manifest.
├── tsconfig.json             ← For local IntelliSense only; MakeCode ignores it
├── main.ts                   ← Entry point. All top-level code runs at boot.
├── *.ts                      ← Additional game-logic files (must be listed in pxt.json files[])
├── assets.json               ← Asset editor metadata index (autogenerated; don't hand-edit)
├── images.g.jres             ← Generated: image asset data (base64). DO NOT EDIT.
├── images.g.ts               ← Generated: namespace shim. DO NOT EDIT.
├── tilemap.g.jres            ← Generated (if any tilemap assets). DO NOT EDIT.
├── tilemap.g.ts              ← Generated. DO NOT EDIT.
├── music.g.jres              ← Generated (if any song assets). DO NOT EDIT.
├── music.g.ts                ← Generated. DO NOT EDIT.
├── main.blocks               ← Present if project was ever opened in Blocks view
├── README.md
├── pxt_modules/              ← Dependencies populated by `mkc install` — GITIGNORE
└── built/                    ← Build artifacts — GITIGNORE
```

## `mkc.json` (autocreated by `mkc init`)

`mkc init arcade` writes an `mkc.json` automatically with the target pinned to the editor version it downloaded. Typical scaffolded contents:

```json
{
    "targetWebsite": "https://arcade.makecode.com/",
    "minEditorVersion": "1.13.10"
}
```

You can extend it with `links`, `overrides`, or `include` (see `references/cli.md`). For most projects the default scaffold is fine and the file just sits there.

## Scaffolded vs. authored `pxt.json`

`mkc init arcade` produces a minimal `pxt.json`:

```json
{
    "name": "my-project",
    "version": "0.0.0",
    "files": ["main.ts"],
    "supportedTargets": ["arcade"],
    "dependencies": {
        "device": "*"
    },
    "testDependencies": {}
}
```

That's enough to build. Add `description`, `preferredEditor: "tsprj"`, and `testFiles: ["test.ts"]` if you want them, but they're optional.

## Full `pxt.json` schema

Authoritative source: https://makecode.com/extensions/pxt-json

```typescript
interface PackageConfig {
    name: string;                    // ^[a-z][a-z0-9\-_]+ if public
    description?: string;
    license?: string;
    authors?: string[];
    files: string[];                 // EVERY .ts/.jres/.g.ts/.g.jres/.md must be listed
    additionalFilePath?: string;
    dependencies: { [name: string]: string };
    public?: boolean;
    icon?: string;
    card?: CodeCard;
    documentation?: string;
    version?: string;
    installedVersion?: string;
    targetVersions?: { target: string; targetId: string };
    supportedTargets?: string[];     // ["arcade"]
    fileDependencies?: { [file: string]: string };
    testFiles?: string[];            // files used only when the extension is run directly
    testDependencies?: { [name: string]: string };
    preferredEditor?: string;        // "tsprj" (TypeScript) or "blocksprj" (Blocks)
    assetPack?: boolean;
    palette?: string[];              // 16 hex colors
}
```

### Minimal `pxt.json` — a TypeScript Arcade game with no assets

```json
{
    "name": "my-game",
    "version": "0.0.1",
    "description": "",
    "dependencies": {
        "device": "*"
    },
    "files": [
        "main.ts",
        "README.md"
    ],
    "testFiles": ["test.ts"],
    "supportedTargets": ["arcade"],
    "preferredEditor": "tsprj"
}
```

### Realistic `pxt.json` — with assets and an extension

```json
{
    "name": "my-game",
    "version": "0.0.1",
    "description": "",
    "dependencies": {
        "device": "*",
        "arcade-text": "github:microsoft/arcade-text#v1.3.0"
    },
    "files": [
        "main.ts",
        "battle.ts",
        "level-data.ts",
        "README.md",
        "assets.json",
        "images.g.jres",
        "images.g.ts",
        "tilemap.g.jres",
        "tilemap.g.ts",
        "music.g.jres",
        "music.g.ts"
    ],
    "testFiles": ["test.ts"],
    "supportedTargets": ["arcade"],
    "preferredEditor": "tsprj"
}
```

### Custom palette (optional)

Override the default 16-color palette by adding to `pxt.json`:

```json
"palette": [
    "#000000", "#ffffff", "#ff2121", "#ff93c4", "#ff8135", "#fff609",
    "#249ca3", "#78dc52", "#003fad", "#87f2ff", "#8e2ec4", "#a4839f",
    "#5c406c", "#e5cdc4", "#91463d", "#000000"
]
```

Index 0 must remain transparent (color is ignored). See `references/assets.md` for full palette details.

## Rules for `files[]`

Anything MakeCode should load **must** appear in `files[]`:
- All `.ts` (game code)
- All `.jres` and `.g.jres` (assets)
- All `.g.ts` (asset shims)
- `README.md`
- `main.blocks` if you want the Blocks view to keep working
- Markdown doc files referenced as block help (`docs/*.md`)

Files NOT in `files[]` are invisible to MakeCode (but can still live in the repo — source PNGs, CI configs, screenshots).

**When adding a new `.ts` file**: create it, add the filename to `files[]`, save. Forgetting to update `files[]` is one of the most common "code is not running" mistakes.

## `.gitignore` — canonical contents

```
# MakeCode
built
node_modules
yotta_modules
yotta_targets
pxt_modules
_site
*.db
*.tgz
.header.json
```

The non-negotiable entries: `pxt_modules/` and `built/`. Both regenerate locally and break GitHub round-tripping if committed.

## `tsconfig.json` — local IntelliSense only

Some repos ship a minimal `tsconfig.json` so VS Code resolves types from `pxt_modules/`. The MakeCode compiler itself ignores this file. A typical contents:

```json
{
    "compilerOptions": {
        "target": "es5",
        "module": "commonjs",
        "strict": false,
        "noImplicitAny": false,
        "experimentalDecorators": true,
        "noEmitOnError": true,
        "noEmit": true
    },
    "include": ["**/*.ts", "pxt_modules/**/*.ts"],
    "exclude": ["node_modules", "built"]
}
```

This is purely a developer-ergonomics file. The build still runs through `mkc build -j`.

## Adding extensions

Two paths:

**1. Edit `pxt.json` directly:**
```json
"dependencies": {
    "device": "*",
    "arcade-character-animations": "github:microsoft/arcade-character-animations#v0.0.7"
}
```
Then run `mkc install`.

**2. Use `mkc add`:**
```bash
mkc add https://github.com/microsoft/arcade-character-animations
```
Mutates `pxt.json` and pulls the extension.

**3. Use the web editor's extension picker**, commit, then `git pull` locally. This is the most reliable path for finding the right version.

## Multi-file projects

Split logic across files when `main.ts` exceeds ~300 lines or has clearly separable concerns:

```
main.ts           ← entry point, scene wiring
sprite-kinds.ts   ← namespace SpriteKind { export const X = … }
level-data.ts     ← namespace levels { export const all: Level[] = [ … ] }
enemy-ai.ts       ← namespace enemies { export function update(e: Sprite) { … } }
ui.ts             ← namespace ui { export function showMenu() { … } }
```

Each file references the others via namespace qualification (`levels.all`, `enemies.update`). No `import` statements. All files must be listed in `pxt.json` `files[]`.

## What NOT to commit

- `pxt_modules/` — regenerated by `mkc install`.
- `built/` — regenerated by `mkc build`.
- `node_modules/` — irrelevant to the MakeCode build, but commonly present if you've added Jest tests (see `references/testing.md`).
- `.header.json` — local editor state.
