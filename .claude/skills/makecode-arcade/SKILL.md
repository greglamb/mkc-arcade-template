# MakeCode Arcade

A skill for working on MakeCode Arcade games locally with Claude Code while the user round-trips through https://arcade.makecode.com/ via GitHub. Target is the **web simulator only** — no hardware deployment.

## The five rules that prevent most failures

1. **Static TypeScript (STS) is not TypeScript.** No `import`/`export`, no `async`/`await`, no `Promise`, no `Map`/`Set`, no `for...in`, no `var`, no regex, no spread, no user-defined tagged templates. See `references/static-typescript.md` for the full ban list and idiomatic replacements.
2. **The CLI is the npm package `makecode`, not `mkc`.** There is a different npm package literally named `mkc` that is unrelated. Install with `npm install -g makecode`. The binary is exposed as both `makecode` and `mkc`.
3. **Never edit `*.g.ts` or the base64 inside `*.g.jres`.** Both are autogenerated by the asset editor. Hand-edits get clobbered on the next build or web-editor save. Author sprite art as `` img`...` `` literals in real `.ts` files instead.
4. **Only 8 tagged template forms are recognized**: `` img`...` ``, `` tilemap`...` ``, `` hex`...` ``, `` assets.image`...` ``, `` assets.tile`...` ``, `` assets.tilemap`...` ``, `` assets.animation`...` ``, `` assets.song`...` ``. Custom tagged templates do not compile.
5. **`mkc build -j` is the verification step.** After any change, run it. If it doesn't compile, the web editor won't open the project either.

## Workflow

### Starting a session

The user's MakeCode Arcade project is a git repo that is also opened in the web editor at https://arcade.makecode.com/. Before any edits:

```bash
git pull --rebase                       # web-editor may have pushed since last session
mkc install                             # refresh pxt_modules/ if pxt.json changed
```

If `mkc` is not installed:

```bash
npm install -g makecode                 # NOT npm install -g mkc — that's a different package
mkc --version
```

If the directory has no `pxt.json`, this is a fresh start:

```bash
mkc init arcade                         # scaffolds main.ts, pxt.json, mkc.json, tsconfig.json, .github/
echo -e "built\nnode_modules\npxt_modules\n.header.json\n*.db\n*.tgz" > .gitignore
```

`mkc init` does **not** create `.gitignore`. Always add it — the two non-negotiable entries are `built/` and `pxt_modules/`. See `references/project-layout.md` for the full recommended contents.

### Making changes

Default mode is to author logic in `main.ts` (or additional `.ts` files listed in `pxt.json` `files[]`) and sprite art as `` img`...` `` literals inline. Treat editor-generated assets (`*.g.jres`, `*.g.ts`, `assets.json`) as opaque:

- **Sprites and tile images**: write as `` img`...` `` literals. Easy to hand-author up to ~32×32.
- **Tilemaps**: do not author by hand. Ask the user to build them in the web editor and commit; pull and reference via `` tilemap`name` `` or `` assets.tilemap`name` ``.
- **Songs**: do not author by hand. Use the web editor's music editor.
- **Animations**: short frame lists are fine as arrays of `` img`...` ``; longer ones go through the web editor's animation editor.

When adding a new `.ts` file, add it to `pxt.json` `files[]`. If skipped, MakeCode silently ignores the file.

When adding an extension (e.g. `arcade-text`, `arcade-character-animations`), edit `pxt.json` `dependencies` and run `mkc install` so local IntelliSense resolves the new APIs.

### Verifying

```bash
mkc build -j                            # JS build, ~3-10s; this is your compile gate
```

If `mkc build -j` passes, the project will open and run in https://arcade.makecode.com/. If it fails, fix locally — the web editor surfaces the same errors but with more friction.

Optional during longer edit sessions:

```bash
mkc serve                               # http://127.0.0.1:7001 watch loop
```

This serves a local simulator. Useful for tight iteration without round-tripping to the web editor.

### Finishing

```bash
git add . && git commit -m "<topical message>" && git push
```

The user will pull these changes in https://arcade.makecode.com/ via the GitHub button. When the user pushes their own edits (asset changes, gameplay tweaks), git-pull on the next session.

Do **not** commit `pxt_modules/` or `built/`. Both should already be in `.gitignore`; if a fresh repo lacks them, add them.

## When to stop and ask the user to use the web editor

Some tasks are not worth attempting locally. Stop and ask the user to handle these in https://arcade.makecode.com/ and commit, then pull:

- Building a new tilemap, even small (the base64 payload format isn't safe to hand-edit).
- Composing a new song or sound effect using the modern Music Editor.
- Renaming an asset that already exists in `assets.json` (display-name remapping touches multiple files atomically).
- Importing or removing an extension via search (technically doable by editing `pxt.json` + `mkc install`, but the editor's extension picker is faster and surfaces version pickers).

For sprite art, palette tweaks, game logic, refactors, balancing, level-data tables, and adding new gameplay systems — work locally.

## Verification checklist before declaring a change done

- [ ] `mkc build -j` exits 0
- [ ] Any new `.ts` file is listed in `pxt.json` `files[]`
- [ ] `pxt_modules/` and `built/` are still gitignored
- [ ] No `import`/`export`/`async`/`await`/`Promise`/`Map`/`Set`/`var`/`for...in` introduced (grep for these as a fast self-check)
- [ ] No edits to `*.g.ts` files (these are autogenerated)
- [ ] Commit message describes the change at a level useful to someone reading diffs in the web editor

## Quick reference: minimal `pxt.json`

```json
{
    "name": "my-game",
    "version": "0.0.1",
    "description": "",
    "dependencies": {
        "device": "*"
    },
    "files": [
        "main.ts",
        "README.md"
    ],
    "testFiles": ["test.ts"],
    "supportedTargets": ["arcade"],
    "preferredEditor": "tsprj",
    "languageRestriction": "javascript-only"
}
```

`languageRestriction: javascript-only` removes the **Blocks** tab in the web editor so it can't be clicked — the robust guard against TS→Blocks clobber. See `references/github-workflow.md` ("Locking the project to JavaScript-only"). For projects with assets, see `references/project-layout.md`.

## Quick reference: hello sprite

```typescript
namespace SpriteKind {
    export const Coin = SpriteKind.create()
}

let player = sprites.create(img`
    . . . f f f f . . .
    . . f 1 1 1 1 f . .
    . f 1 5 1 1 5 1 f .
    . f 1 1 1 1 1 1 f .
    . f 1 5 5 5 5 1 f .
    . . f 1 1 1 1 f . .
    . . . f f f f . . .
`, SpriteKind.Player)
controller.moveSprite(player, 100, 100)
scene.cameraFollowSprite(player)

sprites.onOverlap(SpriteKind.Player, SpriteKind.Coin, (p, c) => {
    c.destroy()
    info.changeScoreBy(1)
})
```

That's the minimum for a working game — palette chars (`.`, `1`-`f`) map to the default 16-color palette documented in `references/assets.md`.
