# MakeCode Arcade project (template)

A MakeCode Arcade game, edited in two places:
- Locally via Claude Code (this folder)
- The web editor at https://arcade.makecode.com/ via GitHub round-trip

The web simulator is the only deployment target — no hardware.

## Read first

Use the `makecode-arcade` skill (bundled in `.claude/skills/`). Always start by reading its `references/pitfalls.md` — it catalogs the ~30 things that look like valid TypeScript but break under Static TypeScript (STS), MakeCode's compiler.

The five most-violated rules:

1. **STS is not TypeScript.** No `import`/`export`, `async`/`await`, `Promise`, `Map`/`Set`, `for...in`, `var`, regex, spread, or user-defined tagged templates.
2. **The CLI is `npm install -g makecode`, not `mkc`.** The binary works as both `makecode` and `mkc`. A different unrelated npm package is literally named `mkc` — do not install it.
3. **Never edit `*.g.ts` files or the base64 inside `*.g.jres`.** Both are autogenerated by the asset editor and clobbered on every web-editor save. Author sprite art as `` img`...` `` literals in real `.ts` files instead.
4. **Only 8 tagged templates are recognized:** `` img`...` ``, `` tilemap`...` ``, `` hex`...` ``, `` assets.image`...` ``, `` assets.tile`...` ``, `` assets.tilemap`...` ``, `` assets.animation`...` ``, `` assets.song`...` ``.
5. **`mkc build -j` is the verification step.** Run it after every change. If it doesn't compile locally, the web editor won't open the project either.

## Session start

```bash
git pull --rebase     # the web editor may have pushed since last session
mkc install           # only needed if pxt.json dependencies changed
```

If `mkc` is missing: `npm install -g makecode`.

## When making changes

- Game logic and sprite art (`` img`...` `` literals): edit locally.
- Tilemaps, songs, large animations: **stop and ask the user to author these in the web editor**, commit, then pull.
- New `.ts` files: add the filename to `pxt.json` `files[]`, or MakeCode silently ignores them.
- New extensions: edit `pxt.json` `dependencies`, then run `mkc install`.
- Never touch `*.g.ts` or the base64 in `*.g.jres`.

## Before committing

```bash
mkc build -j          # must exit 0
```

## Project conventions

### JavaScript-only lock

`pxt.json` is locked to JavaScript-only editing via two fields:

- `"languageRestriction": "javascript-only"` — the web editor **removes the Blocks tab entirely** so it can't be clicked. Primary guard against TS→Blocks clobber.
- `"preferredEditor": "tsprj"` — `main.ts` is authoritative and survives round-trips.

`main.blocks` is **not** listed in `files[]`. Do not re-add it. **If the Blocks tab ever reappears** (`languageRestriction` got stripped on a round-trip), do not click it — restore the field instead. Clicking it triggers a TS→Blocks conversion that can silently rewrite `main.ts`. See the skill's `references/github-workflow.md`.

### Refer to assets by auto-id, not display name

Each asset registers two factory aliases — its auto-id (`image1`, `tile1`, `level1`, …) and the user-set display name. The web editor preserves the auto-id alias indefinitely but does NOT rewrite `assets.image`...`` references in `main.ts` when the user renames, so display-name references silently break at runtime (and `mkc build -j` won't catch it). In `main.ts`, prefer auto-ids:

```ts
sprites.create(assets.image`image1`, SpriteKind.Player)
tiles.setCurrentTilemap(tilemap`level1`)
```

### Debug instrumentation via `config.DEBUG`

`config.ts` declares `namespace config { export let DEBUG = false }` (committed value always `false`; STS rejects `export const` here — TS9267). Gate diagnostic `console.log` lines in `main.ts` behind `if (config.DEBUG)`, prefixed `STATE ` (periodic) and/or `EVENT ` (one-shot). The `/play-watch` + `/play-stop` commands and `tests/` harness consume those prefixed lines — see the skill's `references/testing.md` (Tier 4).

### Local dev (Makefile)

- `make build` — compile gate (`mkc build -j`)
- `make serve` — flip `config.DEBUG` on, start the local simulator at `http://127.0.0.1:7001/`, restore `DEBUG=false` on exit
- `make dev-reset` — force `config.DEBUG` back to `false` if a hard kill left it stuck
- `make clean` — wipe `built/`

## Finishing

```bash
git add . && git commit -m "<topical message>" && git push
```

The user pulls in https://arcade.makecode.com/ via the GitHub button. Commit messages show up in the web editor's diff view — keep them topical and short.

## Don't commit

- `pxt_modules/` — regenerated by `mkc install`
- `built/` — regenerated by `mkc build`
- `node_modules/` / `tests/node_modules/` — irrelevant to the MakeCode build
